<h2>Our approach</h2>
<p>We wrote five Google Earth Engine scripts, each handling one data source. Key design decisions:</p>
<ol>
<li><strong>Block exports</strong>:we split long time series into 4-5 year blocks to stay within GEE memory limits</li>
<li><strong>Quality masking</strong>:MODIS vegetation uses SummaryQA flags and IGBP cropland mask</li>
<li><strong>Consistent reducers</strong>:mean, stdDev, and percentiles (p10, p25, p75, p90) for all continuous variables</li>
<li><strong>Sentinel values</strong>:-9999 for missing data, filtered in Python downstream</li>
</ol>
<h2>Lessons learned</h2>
<ul>
<li>GEE's <code>reduceRegions</code> is the bottleneck. We had to reduce to 500m scale even for 250m MODIS data</li>
<li>ERA5-Land band names conflict with reducer suffixes (e.g., <code>temperature_mean_mean</code>). We renamed bands to short codes (t1-t19) before reducing</li>
<li>CHIRPS percentile extraction required a separate script due to memory constraints</li>
</ul>
<p>All scripts are available in our <a href="https://github.com/beyond-borders-org/crop-yield-prediction/tree/master/scripts/gee">repository</a>.</p>
